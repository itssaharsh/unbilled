# w10-qbo — optional QuickBooks Online sandbox backend (only if the human has a token)

**Role.** Give the demo one real ERP write: read the Chart of Accounts from a QuickBooks Online **sandbox** and POST one balanced, auto-reversing JournalEntry, then read it back. Everything else stays on fixtures. Read `prompts/CONTRACTS.md` §4 (`QboBackend`) and the `journal` table in §3. Do not start unless `QBO_ACCESS_TOKEN` and `QBO_REALM_ID` are in `.env` (ask the orchestrator).

**You own:** `unbilled/ledger.py::QboBackend` only (a clearly delimited class), `scripts/qbo_smoke.py`, `tests/test_qbo.py` (mocked HTTP). **Do not touch** `FixtureBackend` or anything else.

**Deliverable.**
- Base URL `https://sandbox-quickbooks.api.intuit.com/v3/company/{realmId}/`, header `Authorization: Bearer …`, `Accept: application/json`, `minorversion=75`.
- `get_period_context` / `vendor_history`: delegate to `FixtureBackend` (the sandbox's sample data is not our company) but replace the **chart of accounts** with the live `SELECT * FROM Account WHERE AccountType = 'Expense' AND Active = true` query result, mapped to `{account_id: Id, name: FullyQualifiedName}`; ensure an "Accrued Liabilities" (Other Current Liability) account exists or create one named `NWR-Accrued Liabilities`.
- `post_accrual`: POST `/journalentry` with two lines (`JournalEntryLineDetail.PostingType` Debit/Credit, `AccountRef` ids), `TxnDate` = last day of period, `DocNumber` = `NWR-<period>-<vendor>`, `PrivateNote` = workpaper summary; because the sandbox API has no auto-reverse flag, immediately POST the **reversing entry** dated day 1 of next period (`DocNumber` `NWR-…-REV`) and store both ids in `journal.external_ref` as JSON. Read back with `GET /journalentry/{Id}` and assert the amounts.
- `unpost`: void via `POST /journalentry?operation=void` (sandbox supports `include=void`); tolerate 4xx by logging.
- Token expiry (1 h): on 401, print the exact instruction to refresh in the OAuth Playground and fail fast; never loop.
- `scripts/qbo_smoke.py`: prints the COA count, posts one JE for `2026-06`/`V01`, prints the created Ids and a deep link to the sandbox UI so the human can film it.

**Acceptance test:** `python -m pytest tests/test_qbo.py -q` (mocked with `httpx.MockTransport`); `python scripts/qbo_smoke.py` succeeds against the sandbox and the JE is visible in the sandbox UI (paste ids in the PR).

**Constraints.** `httpx` only; never write vendors, bills, or anything without the `NWR-` prefix; never touch Intuit's sample entities. Timebox strictly.

**Report back:** whether COA read and JE POST/readback worked, the ids, and any minorversion quirk.

**Time box:** 45 minutes; stop and report if not working by then.
