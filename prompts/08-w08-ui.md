# w08-ui — the one screen judges see

**Role.** You build the entire frontend: one screen plus a right drawer, reading `web/public/data/*.json` through the FastAPI app and writing through `/api/*`. It must make the learning visible in eight seconds: a red variance column becoming green, a memory panel that grows with counters ticking and rules greying out, a chart with a flat control line, and a journal entry whose every line cites a rule you can click. Read `prompts/CONTRACTS.md` §9–§10 first. Start against the **fake** `runs.json`/`worksheet_2026-04.json`/`ledger_history.jsonl` the orchestrator committed; swap to real data when `w09` lands (same shapes).

**You own:** everything under `web/`. **Do not touch** Python files. If a data shape is missing something you need, request it from the orchestrator in your PR rather than changing `metrics.py`.

**Stack:** Vite + React 18 + TypeScript + Tailwind + Recharts. Dev server proxies `/api` and `/data` to `http://localhost:8787`. No router, no auth, no global state library (React state + a small `useData()` hook with refetch after writes). `npm run build` must pass typecheck.

**Design read (declare it at the top of your first message, then follow it):** *Operate-mode product UI for a controller — dense instrument panel, one sans family (Inter or IBM Plex Sans via Google Fonts, with fallback stack), restrained neutral palette, semantic state colors only (red variance / green within materiality / amber escalated / grey deprecated), polish spent on the three evidence surfaces.* Dials: VARIANCE 4 / MOTION 3 / DENSITY 7. Anti-defaults: no purple gradients, no glassmorphism, no hero, no fake screenshots, no wrapped buttons, one label per intent, empty and loading states designed, dark theme locked (not a toggle).

**Skills to use (they are installed in `~/.claude/skills`):** load `impeccable` → run `node ~/.claude/skills/impeccable/scripts/context.mjs` once → mode **Operate** → read `reference/operate.md` and `reference/craft-floor.md` before editing (skip the concept-dice/new-work ritual; no time) → build → one `polish` pass at the end. Apply `taste-skill` §3–4 as your pre-flight gate (typography scale, color calibration, layout discipline, no div-built fake product shots). Load `dataviz` before writing the chart and KPI tiles (categorical vs sequential color, axis/tooltip rules, stat-tile hierarchy).

**Screen spec.**
- **Header:** product name small; period stepper `Apr · May · Jun · Jul` (keyboard ← →); four KPI tiles — accrual MAPE, controller touches, $/close, pass^2 — each with delta vs the first close and a tiny sparkline across closes.
- **Center — accrual worksheet** (one row per vendor from `worksheet_<period>.json`): `vendor · last-3 actuals sparkline · method chip · ESTIMATE · confidence bar · rule pills (PRE-014, click → opens that rule in the drawer) · ACTUAL (or "pending — arrives by <period>") · VARIANCE badge` (green within materiality, red otherwise, grey when pending). Under each posted accrual a subdued **day-1 reversal row** (`Reversal 2026-05-01 · Dr 2100 / Cr 6100`). Rows with `route=escalated` show an amber "in review" state until resolved.
- **Right drawer, two tabs.** *Review Queue*: cards for escalated rows with the recommendation, confidence, evidence (last-3 actuals, lag stats, open PO), and **Approve / Edit / Reject**; Edit and Reject require a reason code (`wrong_method · wrong_period · should_not_accrue · immaterial · superseded_by_po · vendor_terms_changed`) plus a note; submit → `POST /api/review` → refetch. *Precedent Ledger*: rule cards (id, kind, scope, trigger → action, rationale, provenance line "learned 2026-05 from Dana's edit on Acme Legal · reason: wrong_method", applied/helpful/harmful pills, status chip incl. `REJECTED · rolled back · +0.04 MAPE`, version), filters by kind and source, an `Apr ↔ Jul` diff toggle (added = green left border, deprecated = struck + grey, changed = amber), and an inline-editable textarea that `POST /api/rule`s.
- **Bottom strip — convergence chart:** MAPE by close for `main` with `memory_off` overlaid flat and `validator_off` if present; second small chart or toggle for touches and $/close; one annotated regression point if the data has one (the annotation text comes from `runs.json` `summary.notes` if present, else omit).
- **Workpaper modal:** click any posted estimate → rendered markdown workpaper, citations as pills, reversal reference, **Unpost** button → `POST /api/unpost` → refetch.
- **Validator banner:** when the selected close has a `validator_log` row, show `Validator · canary MAPE 0.31 → 0.19 · cost −8% · COMMIT` (or ROLLBACK in red).

**Acceptance test:** `cd web && npm ci && npm run build` passes; `make demo` (with `LLM_PROVIDER=stub` and no API key) renders all four closes from the committed data; Approve/Edit/Reject/Unpost/rule-edit round-trip and the UI reflects the change without reload; Lighthouse-ish sanity: no console errors, no layout shift on drawer open, 1280×800 and 1920×1080 both fine; keyboard focus visible.

**Constraints.** Keep to ~10 components. No placeholder copy left anywhere. No dependency beyond the stack above (icons: inline SVG or `lucide-react` only). Commit screenshots of the four closes to `docs/screenshots/` for the README.

**Report back:** component list, any data fields you had to fake, and the screenshot paths.

**Time box:** 3 hours (ship a usable first version in 90 minutes, then polish).
