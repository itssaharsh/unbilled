# CONTRACTS.md — frozen interfaces for every Unbilled worker

Read this before writing any code. If something here is marked **TBD**, the orchestrator resolves it before your session starts; if you find a real contradiction, report it to the orchestrator in your PR description instead of silently changing the contract.

## 0. Product in one paragraph

**Unbilled** runs the accrual step of a month-end close as the *preparer*, with the accountant as *reviewer*. For each vendor at close it decides whether a liability exists for goods/services received but not yet invoiced, estimates the amount, books an **auto-reversing journal entry** dated period-end (reversal on day 1 of the next period), and writes a workpaper citing source rows and rule IDs. Low-confidence cases go to a Review Queue where the human's Approve/Edit/Reject carries a **reason code** — that reason is the learning write. Next close, when the real invoice arrives, the agent scores itself (`|estimate − actual| / actual`), a Reflector proposes typed rule changes, a deterministic Curator merges them into the **Precedent Ledger**, and a **Validator** replays the candidate ledger on two already-closed canary periods and commits only if error improves. Headline metric: accrual MAPE falling across four closes, with a memory-OFF ablation flat.

## 3. SQLite schema — `unbilled.db` (DDL lives in `unbilled/config.py:init_db`)

```sql
CREATE TABLE precedent (
  id TEXT PRIMARY KEY,            -- 'PRE-014'
  kind TEXT NOT NULL,             -- accrual_method | cutoff_lag | coding | tool_fact
  scope TEXT NOT NULL,            -- 'vendor:V01' | 'global'
  trigger TEXT NOT NULL,          -- plain-English condition, used for fuzzy retrieval
  action TEXT NOT NULL,           -- plain-English instruction (may contain a JSON snippet, e.g. {"method":"run_rate","multiplier":1.08})
  rationale TEXT NOT NULL,
  source TEXT NOT NULL,           -- human_correction | inferred_from_data | tool_error
  provenance TEXT NOT NULL,       -- JSON: {period, bill_ids:[], reviewer, reason_code, run_id}
  applied INTEGER DEFAULT 0, helpful INTEGER DEFAULT 0, harmful INTEGER DEFAULT 0,
  status TEXT NOT NULL,           -- proposed | active | deprecated | rejected
  canary_delta TEXT,              -- JSON: {mape_before, mape_after, cost_before, cost_after, decision}
  created_period TEXT NOT NULL, updated_period TEXT NOT NULL, version INTEGER DEFAULT 1
);
CREATE TABLE estimate (
  id INTEGER PRIMARY KEY, run_id TEXT NOT NULL, period TEXT NOT NULL, vendor_id TEXT NOT NULL,
  arm TEXT NOT NULL, seed INTEGER NOT NULL,
  should_accrue INTEGER NOT NULL, method TEXT, amount REAL, confidence REAL, account_id TEXT,
  cited_rule_ids TEXT,            -- JSON list
  route TEXT NOT NULL,            -- auto_posted | escalated
  human_action TEXT, human_reason_code TEXT, human_note TEXT, final_amount REAL,
  actual_amount REAL, variance_pct REAL, scored_in_period TEXT,
  in_tokens INTEGER, out_tokens INTEGER, cache_read_tokens INTEGER, cost_usd REAL, latency_ms INTEGER, tool_calls INTEGER,
  workpaper_md TEXT, journal_id TEXT
);
CREATE TABLE journal (
  journal_id TEXT PRIMARY KEY, period TEXT, vendor_id TEXT, estimate_id INTEGER,
  entry_date TEXT, reversal_date TEXT, lines TEXT,  -- JSON [{account_id, debit, credit, memo}]
  status TEXT,                    -- posted | reversed | unposted
  external_ref TEXT               -- QBO JournalEntry Id when the qbo backend is used
);
CREATE TABLE run (
  run_id TEXT PRIMARY KEY, period TEXT, arm TEXT, seed INTEGER, started_at TEXT, finished_at TEXT,
  ledger_snapshot_before TEXT, ledger_snapshot_after TEXT, totals TEXT  -- JSON
);
CREATE TABLE ledger_snapshot (snapshot_id TEXT PRIMARY KEY, created_at TEXT, period TEXT, rules TEXT); -- JSON dump of precedent rows
CREATE TABLE validator_log (
  id INTEGER PRIMARY KEY, period TEXT, candidate_snapshot TEXT, incumbent_snapshot TEXT,
  mape_incumbent REAL, mape_candidate REAL, cost_incumbent REAL, cost_candidate REAL,
  decision TEXT,                  -- commit | rollback
  delta_ops TEXT                  -- JSON list of the ops evaluated
);
```

## 5. The five tools (names, params, returns) — implemented in `tools.py`, exposed to the Estimator

All tools: `strict: true`, `additionalProperties: false`, every param `required` (use `null`-able types for optional). Errors are returned as tool results with `is_error: true` and an **instructive** message that says what to do instead.

1. `close_get_period_context(period: str, response_format: "concise"|"detailed")` → `{period, close_date, arrived_bills: [{bill_id, vendor_id, service_period, amount, account_id, received_date, po_id}], open_pos: [...], anticipated_vendors: [{vendor_id, name, last_service_period_billed, typical_amount, typical_lag_days}], active_expense_accounts: [{account_id,name}]}`. Concise caps bills at 60 and truncates memos; detailed returns full lines. Truncation notice tells the agent to call `vendor_history` for a specific vendor.
2. `vendor_history(vendor_id: str, months: int)` → `{vendor_id, per_period: [{service_period, amount, account_id, received_date, lag_days, po_id}], stats: {mean_amount, trailing_3_mean, lag_mean_days, lag_sd_days, periods_with_no_bill: []}, open_pos: [...]}`.
3. `precedent_search(query: str, kind: string|null, k: int)` → `{rules: [{id, kind, scope, trigger, action, rationale, helpful, harmful, status}]}` (active only; also used to log `applied`).
4. `precedent_propose(delta_ops: [...])` → used by the Reflector only (not in the Estimator's toolset).
5. `close_post_accrual(vendor_id: str, period: str, amount: number, method: str, account_id: str, workpaper_md: str, cited_rule_ids: [str], confidence: number)` → if `confidence >= 0.85` posts a balanced JE `Dr <account_id> / Cr 2100` dated `last day of period`, `reversal_date = first day of next period`, returns `{journal_id, status: "posted", reversal_date}`; else returns `{status: "escalated", escalation_id}`. Errors: bill already posted for this vendor/service period → `"Bill B0187 for V01 already covers service period 2026-06; accruing would double-count. Accruals are for received-not-invoiced only — check anticipated_vendors."`; unknown account → list of valid expense accounts.

**Estimator output** is a structured decision (`output_config.format` JSON schema = `Decision`), not free text. The Estimator's toolset is tools 1, 2, 3, 5.

## 7. Model / API rules (verified; violations return HTTP 400)

- **SDK:** `anthropic` **1.x** is installed (1.4.0). In 1.x, `temperature`/`top_p`/`top_k` are **not keyword arguments** of `messages.create()` (TypeError) — pass them via `extra_body={"temperature": 0.2}` and only for Haiku 4.5. The SDK's HTTP layer is `httpx2`; any transport/mocks handed to the SDK must come from `httpx2`, and the plain `httpx` package is only for the QBO client.
- Estimator default `claude-haiku-4-5`: temperature allowed via `extra_body` (seed variation: seed 1 → 0.2, seed 2 → 0.7; validator replays at 0.0). **Do not pass `output_config.effort`** (rejected on Haiku). Structured output via `output_config={"format": {"type": "json_schema", "schema": ...}}`.
- Reflector default `claude-sonnet-5` (or `claude-opus-5`): `thinking={"type": "adaptive"}`; **never pass `temperature`, `top_p`, `top_k`, or `budget_tokens`**; no assistant prefill.
- Tools: `strict: True` on the tool definition + `additionalProperties: False` + full `required`.
- Parse tool inputs with `json.loads`, never string-match. Return all `tool_result` blocks for one assistant turn in one user message; failed tools use `is_error: true`.
- Concurrency: `MAX_CONCURRENCY` (env, default 4); retry on 429/5xx with exponential backoff + jitter (the SDK retries twice; add an outer retry of 3 with 5–20 s sleeps and log every 429).
- OpenAI-compatible path (TensorMux `glm-4-7-flash`, GPT-5 nano): same normalized interface; tool schemas converted to `functions`; JSON output via `response_format` json_schema when supported, otherwise a post-hoc `json.loads` of the text with one repair retry.
- Neatlogs: `tracing.init()` must run **before** `import anthropic` anywhere; `instrumentations=["anthropic"]` (and `"openai"` when that path is used); `workflow_name="unbilled-close"`.

## 8. Simulated controller (used by `run_close(..., reviewer="simulated")`)

Reads `world_truth.json` (allowed here — it stands in for the human who knows the business). For each escalation: if the estimate is within materiality `max(10%, $500)` of `true_amount` → `approve`; else if `should_accrue` is false → `reject` with reason `should_not_accrue`; else `edit` to `true_amount × (1 + N(0, 0.03))` with reason code chosen by the dominant error: `wrong_method` (amount off by >25%), `wrong_period` (vendor's bill actually arrived before close), `immaterial` (true_amount < $500), `superseded_by_po` (PO fully received and amount known), `vendor_terms_changed` (rate change period). Adds a one-line note in accountant voice. README and video must say the sweep's reviewer is simulated and the recorded demo's reviewer is human.

## 10. FastAPI (`api.py`, served on :8787; Vite proxies `/api` and `/data`)

- `GET /data/{file}` → serves `web/public/data/*`.
- `POST /api/review` `{period, vendor_id, action: approve|edit|reject, amount?, reason_code, note}` → updates `estimate`, posts/unposts the JE, ticks `helpful` (approve) or `harmful` (reject/edit) on `cited_rule_ids`, appends a `human_correction` rule draft as `proposed` when action is edit/reject, re-exports the period worksheet + ledger history. Returns the updated worksheet row + touched rules.
- `POST /api/unpost` `{journal_id}` → status `unposted`, returns the reversing entry reference.
- `POST /api/rule` `{rule_id, trigger?, action?, rationale?, status?}` → edits a rule, bumps `version`, re-exports.
